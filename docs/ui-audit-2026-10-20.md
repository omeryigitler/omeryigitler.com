Scope: public homepage, project archive, shared CSS/JS, intro build pipeline, metadata of privacy/cookies pages and repository inventory. This is source-based review, not a completed visual/mobile/browser audit. Local runtime unavailable; live browser unavailable. No claim of measured performance, contrast compliance or external link availability.

## Fixed on the existing PR branch

- Mobile archive filters were hidden at <=767px: restore wrapping, 44px category controls.
- At <=980px with a mouse, the magnifier was hidden while CSS hid the native pointer and the global pointer excluded search. Activate the magnifier and cursor suppression together only at >=981px with a fine pointer; global pointer handles the remaining widths.
- Mobile result status used display:none: retain its screen-reader live announcement without crowding the search input.
- Desktop project cards used fixed height plus overflow:hidden: use a minimum height and wrap long titles/metadata so content can grow.
- Touch tablets relied on hover for desktop project previews: provide an inline preview while retaining card information.
- Cached failed images missed the error event; successful image loads did not clear failure state: handle both cached completion and load/error recovery. With no IntersectionObserver, show mobile previews directly.
- Archive search now uses search input semantics; active Projects navigation has aria-current.
- Removed hidden archive ticker/centerline markup and unused ticker, obsolete headline timer and absent footer observer code from projects-page.js. Kept the existing logo behavior.
- Version projects-page.js by content in build wiring so the cleanup reaches returning visitors.
- Project archive Google Analytics now follows the same CookieYes-gated loading as the homepage.
- Contact submission localStorage parsing/writes could throw on blocked storage or non-array JSON: guard these operations; API protection is unchanged.

## Remaining, deliberately not deleted blindly

- Git tracks 5,404 node_modules files (~286 MB) despite .gitignore. Remove in a dedicated dependency cleanup only after clean installation and API packaging verification. Files in a dependency tree are not application dead code.
- Legacy HTML and React project/process entry points exist. Their absence from the current homepage alone does not establish that they are unused everywhere; archive routes/build consumers need verification before deletion.
- CSS has layered historical overrides and old project device selectors. Consolidating all of them without rendered desktop/mobile comparisons risks changing the restored design.
- Privacy/cookies pages have viewport metadata; full legal content and backend/admin/security behavior were not audited.
